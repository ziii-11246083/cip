# 第 18 章 系統功能與資料一致性矩陣

> 盤點基準：2026-08-20 的 `08/20` 分支工作樹。本章只依可定位的 route、function/service、Supabase client 呼叫與 repository migration 判定；未連線正式 Supabase，所以不把 Dashboard 中無法從 repo 證明的物件宣稱為已部署。

## 18-1 狀態定義

| 狀態 | 判定原則 |
|---|---|
| `implemented` | 已有可達 UI/API 與實際執行邏輯；若依賴外部 API，仍可能因網路/憑證而降級。 |
| `partial` | 已有部分 runtime，但持久化 schema/migration、資料品質、完整 UI 或部署證據不足。 |
| `planned` | 只有文件或資料契約，沒有可達 route + CRUD/migration 證據。 |
| `deprecated` | 舊文件/舊設計聲稱，現行 runtime 不執行。 |

## 18-3 六條必查資料流

| 流程 | 實際輸入 | 實際處理/寫入 | 不得宣稱 |
|---|---|---|---|
| Scam | 可疑文案 `text` | rules -> local RAG -> LLM -> trace；不寫 scam log | 已掃描合約、網域、GMGN、WHOIS、PTT 或鏈上活動 |
| RAG | query/request snapshot | retrieval -> actually-injected sources -> answer trace；feedback 以 user JWT/RLS upsert | 只有回答即代表準確；尚需 baseline 與持續評測 |
| 會員 | Supabase session 或 Demo session | UI gating + `token_required`；`/member` 展示模擬交易資產 | Demo 等於付費訂閱，或會員中心是真實交易所資產 |
| 模擬交易 | symbol/side/amount 與即時價 | Supabase RPC（若可用）或本地 JSON fallback | 已送單到真實交易所；repo 已含完整 RPC migration |
| 壓力測試 | 前端提供的當下模擬組合快照、合成期間與 seed | 獨立計算 normal/bull/bear/black_swan；不寫 `sim_*` | 是歷史回測、價格預測、投資建議，或會改動模擬帳本 |
| 訂閱 | 目前無 runtime 輸入 | 僅定價與 schema 文件 | 已有 checkout、webhook、entitlement、扣款或自動續訂 |
| external account | Ethereum Mainnet 公開地址（不收 secret） | JWT/entitlement -> Alchemy 唯讀查詢 -> real snapshot；與 sim 完全分離 | 已支援交易所、全鏈、自動排程，或 migration 已部署 |

## 18-5 文件維護規則

1. 功能是否完成以 route + runtime + data path 為準，不以畫面或表名存在為準。
2. DB 物件只有概念欄位時必須標 `planned`；有 client call 但沒有 repo migration 時標 `partial`。
3. Mermaid 規劃圖標題必須含「規劃/未實作」，不得與現行 runtime 流程混畫。
4. 所有 ✅/「已實作」宣稱必須能定位到程式、migration 或可重複測試；只完成文件設計不等於產品完成。
