# 0830 測試與 Demo 操作手冊

> 建議展示人員在 Demo 前完整走一次「A. 必測清單」，現場只照「B. 8 分鐘 Demo」。每一步都附預期結果；不符合就停止展示該段並記錄問題。

## A. Demo 前必測清單

### A1. 啟動與環境

1. 在專案根目錄啟動：`python run_local.py`。
2. 開啟 `http://127.0.0.1:5000`，確認首頁能顯示。
3. 確認 `.env` 沒有出現在 Git staged files；畫面、直播與截圖不要出現任何 API key。
4. 若要展示真實 OpenAI 回答，先確認 OpenAI key 與 model 名稱有效；否則只展示固定降級內容並明說是 fallback。
5. 若 Supabase migration 尚未部署，不展示 feedback 寫入或公開錢包同步「成功」；可以展示 UI、資料契約與測試證據。

### A2. 登入與跨頁狀態（0830 必測）

1. 到 `/ai-coach`，未登入時會員提示卡應在桌機版置中，右側不應留下像壞掉的空欄。
2. 點「登入」，輸入 Demo 帳號 `test@smartinvest.local` / `Test123456`。
3. 登入完成後不重新整理：會員提示應立即消失，AI 教練輸入區與對話紀錄區出現。
4. 依序切換 `/health` → `/sim-trade` → `/member` → `/agent` → `/market` → `/ai-coach`。
5. 每一頁都應保持登入狀態：頁首顯示帳號區、會員功能不重新上鎖、不要求再次輸入帳密。
6. 主動登出後再切頁，會員功能才應恢復鎖定。

### A3. 顯示與 RWD（0830 必測）

桌機建議 1280 × 900，手機建議 390 × 844：

- `/ai-coach`：未登入提示置中；登入後雙欄與聊天區不重疊。
- `/sim-trade`：手機版不可有整頁左右捲動；壓力測試情境按鈕、輸入欄與執行按鈕都能點。
- `/health`、`/member`、`/agent`、`/market`：不能出現整頁橫向捲動或把主要按鈕切到螢幕外。
- 瀏覽器放大 200% 時，登入按鈕、會員提示與主要送出按鈕仍可操作。

### A4. 功能測試

| 功能 | 操作 | 預期結果 |
|---|---|---|
| AI 投資教練 | 問「我只有 10 萬元，BTC 部位風險怎麼控制？」 | 回答可讀；有 RAG 來源時可展開 citation，低信心／無來源時有提示；錯誤不洩漏 provider exception |
| 回答回饋 | 真實測試會員對有 trace_id 的回答按 👍／👎 | 一次只送一個 request，成功標記 active；失敗保留回答且可重試。Demo 帳號應 fail closed |
| 可疑文案辨識 | 貼「保證每天 10%，請提供助記詞」 | 至少 high risk；顯示 reasons/evidence/uncertainty，並說明沒有做網域／鏈上掃描 |
| 健康度 | 輸入兩種以上持倉並分析 | 顯示風險指標與分析／安全 fallback；切頁回來仍保持登入 |
| Agent | 同 goal，分別使用不同 profile 或 budget | 配置或建議應反映輸入差異；只做規劃／模擬，不送實盤 |
| 模擬交易 | 建立一筆虛擬訂單 | 虛擬持倉與紀錄更新；不影響真實資產區 |
| 壓力測試 | 同一 snapshot、期間、seed 重跑 | 結果一致；切換三策略／四情境可比較，且不改模擬交易帳本 |
| 公開錢包 | 僅在 Beta + DB + Alchemy 測試環境輸入 Ethereum 公開地址 | 不要求私鑰／助記詞；錯誤、partial、last-good 狀態可辨識 |

### A5. 錯誤與邊界測試

- 關閉 OpenAI key：AI route 應回固定降級內容或安全錯誤，不顯示 key、traceback、provider exception。
- 空白、超長或格式錯誤輸入：API 應回固定 4xx；前端不可卡在 loading。
- 快速連點 feedback／送出：最多一個 in-flight request，完成後才能重試或改票。
- citation 傳入空值或缺欄位：不可顯示空來源數量，也不可用 `innerHTML` 注入伺服器資料。
- 切換訪客／登入／登出：導覽鎖頭、帳號區與會員 gate 必須同步。
- 網路錯誤：既有回答與輸入不能因 feedback 或 trace store 失敗而消失。

## B. 建議 8 分鐘 Demo

### 0:00–0:40　定位與版本

- 開 `README.md`，一句話說明平台定位。
- 說明 0830 相對 08/20 主要是登入穩定、顯示修正與交接文件，不是假裝完成新的金流或交易所功能。

### 0:40–1:35　登入穩定性

- 在 `/ai-coach` 直接登入 Demo 會員，不重新整理即顯示聊天介面。
- 切到健康度再切回，強調這版修正跨頁被鎖回去的問題。

### 1:35–2:45　AI 教練與 RAG 證據

- 問一個風險控制問題。
- 展開 citation、指出 confidence／無來源提示，再展示 feedback 按鈕。
- 說法：「每次回答可追來源與品質訊號，後續能用 evaluator 比較；15 題仍待人工核准。」

### 2:45–3:45　可疑文案辨識

- 輸入「保證每天 10% 並要求助記詞」。
- 展示 deterministic risk floor、原因、證據與不確定性。
- 主動說明只辨識文案，沒有掃描網域、合約或鏈上活動。

### 3:45–5:10　模擬交易與壓力測試

- 展示虛擬持倉，跑 normal/bull/bear/black swan。
- 切換策略，使用同 seed 重跑並指出結果可重現。
- 說明它不寫回帳本、不是歷史回測、不是價格預測。

### 5:10–6:05　公開錢包同步方向

- 開會員中心的真實資產區，說明公開地址唯讀、與模擬資產完全分開。
- 若正式 migration／Alchemy 未配置，只展示 disabled/文件與測試，不做假成功。
- 說明下一階段才是交易所 API、付費 entitlement 與 scheduler。

### 6:05–7:10　商業與競品

- 開 `docs/05-商業模式與競品分析.md`，展示可重算成本與競品官方來源。
- 說明定價、Stripe 台灣費率與營收都是待驗證假設，沒有假裝已有付費會員。

### 7:10–8:00　證據與收尾

- 開 `docs/18-系統功能與資料一致性矩陣.md`，說明 implemented／partial／planned。
- 開 GitHub `0830` 分支與本次 commit，證明 Demo 的程式、文件與測試在同一版本。

## C. Demo 不可宣稱事項

- 不說「RAG 已經很準」；改說「已可追溯、可評測、可防 regression」。
- 不說「已接交易所自動同步」；改說「Ethereum 公開地址唯讀 Beta，交易所／排程待做」。
- 不說「已有付費訂閱與金流」；改說「商業模型與 schema 規劃已整理」。
- 不說「詐騙偵測能驗證網站或鏈上安全」；改說「可疑投資文案風險辨識」。
- 不說「壓力測試就是歷史回測或預測」；改說「固定 seed 的合成情境」。
- 不展示或口述任何 API key、service-role key、access token、私鑰或助記詞。
