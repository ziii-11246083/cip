# 第 16 章 模型與資料流說明

> 本章詳細說明系統中每個 AI 功能的輸入→處理→輸出資料流。

## 16-1 AI 對話資料流 (`/api/ai-chat`)

```
【輸入】
├─ user_message: str              # 使用者輸入的文字
├─ risk_profile: str              # 保守型/穩健型/積極型
├─ conversation_id: str (optional) # 既有對話 ID
├─ history: List[Message]          # 歷史訊息 (from Supabase or client)
└─ access_token: str               # Bearer token

【處理】
1. Guardrails: check_input(user_message) → 過濾 prompt injection
2. Conversation Setup:
   ├─ 若有 conversation_id → 載入歷史
   └─ 若無 → 建立新對話 (ai_conversations)
3. Save User Message → ai_messages
4. RAG Retrieval:
   ├─ 關鍵字檢索 investment_rules / scenario_playbooks / market_narratives
   ├─ 若 KB 未載入或檢索失敗 → 跳過 (不影響)
   └─ 組裝 RAG context string
5. Build System Prompt:
   ├─ build_ai_system_prompt(risk_profile)
   └─ + RAG context
6. Build Messages Array:
   ├─ [system, ...history, user_msg]
   └─ 若 client 提供 messages → 使用 client messages
7. LLM Call:
   ├─ model: OPENAI_MODEL (default gpt-5.4)
   ├─ tools: [get_crypto_price_usd]
   └─ stream: false
8. Tool Calling (if any):
   └─ get_crypto_price_usd(symbol) → 查詢 CoinGecko → 回填 tool result → 再次 LLM
9. Save Assistant Message → ai_messages
10. Guardrails: check_output(reply) → 過濾不安全輸出

【輸出】
{
  reply: str,                 # AI 回應文字
  conversation_id: str,       # 對話 ID (後續追蹤用)
  trace_id: str|null,
  citations: list,
  confidence: number|null
}
```

**RAG 注入點**：步驟 4–5（檢索知識 → 組裝 system prompt）
**Fallback**：若 RAG 失敗 → 使用原始 `build_ai_system_prompt()`，無 RAG context
**目前狀態**：implemented with degradation。BM25 為本地主要路徑；Dense/RRF/rerank 受設定與依賴可用性影響，失敗時會降級並記 trace，不代表每次請求都實際走完所有元件。

## 16-2 市場資料流 (`/api/market`, `/api/coingecko`, etc.)

```
【輸入】
├─ (無使用者輸入)

【處理】
1. CoinGecko API Call:
   ├─ /coins/markets (MARKET_COIN_LIMIT=24 or SFI_COIN_LIMIT=20)
   └─ TTL Cache: 300s
2. DataManager.build_historical_df(tickers):
   ├─ yfinance.download() → 90d 歷史價格
   └─ 計算報酬率矩陣
3. RiskModel.calculate_copula_risk(symbol, df, is_stable, price):
   ├─ Beta (OLS regression vs BTC)
   ├─ Clayton Copula fit → λ_lower
   └─ SFI = normalize(w1×Beta + w2×λ + w3×σ_norm) → 0-100
4. Sort & Filter → 回傳

【輸出】
{
  timestamp: str,
  data: [{symbol, name, price_usd, change, risk: {level, score, beta, lambda, corr}}]
}
```

**RAG 注入點**：無（純 Quantitative layer，不經 LLM/RAG）
**目前狀態**：implemented，但實際資料完整性取決於 CoinGecko/yfinance 可用性；空資料是可預期降級，不應稱為無條件完整。

## 16-3 詐騙檢測資料流 (`/api/scam-scan`)

```
【輸入】
├─ text: str                    # 使用者輸入的可疑內容

【處理】
1. Guardrails: 檢查輸入是否為空
2. Deterministic Text Rules:
   ├─ 保證獲利 / 索取助記詞或私鑰 / 冒名客服 / 緊迫匯款
   └─ 建立 triggered_rules 與不可被 LLM 降級的風險下限
3. RAG Retrieval (補充):
   ├─ 檢索 scam_patterns.md → 拿相關案例知識
   └─ 若失敗 → 明確標示降級，仍保留規則判定
4. LLM Call:
   ├─ system_prompt + RAG scam knowledge
   ├─ user content
   └─ structured output: ScamScanResult (risk_level + report)
5. Merge & Guardrails:
   ├─ 取 deterministic 規則風險下限與 LLM 評級的較高者
   ├─ 移除未驗證的外部掃描聲稱
   └─ 組合 evidence / citations / uncertainty

【輸出】
{
  risk_level: "high"|"medium"|"low"|"unknown",
  report: str,                  # 舊客戶端相容欄位
  triggered_rules: str[],
  reasons: str[],
  warnings: str[],
  evidence: object[],
  citations: object[],
  uncertainty: "low"|"medium"|"high",
  trace_id: str|null
}
```

**RAG 注入點**：步驟 3–4（詐騙案例知識 → 補充 system prompt）
**核心邏輯**：可解釋文字規則 + 本地 RAG + LLM 說明；規則高風險不可被 LLM 降級
**目前狀態**：未串接 GMGN、WHOIS、PTT、合約安全或鏈上掃描；不得將文案辨識當成安全保證

## 16-4 Podcast 生成資料流 (`/podcast/generate`)

```
【輸入】
├─ market: str                  # PERSONAL|CRYPTO|ALT|BTC|RISK
├─ risk_level: str
├─ watchlist: list
├─ events: str
└─ portfolio_summary: dict (optional)

【處理】
1. Build Prompt:
   ├─ 組裝市場/風險/關注清單/事件
   └─ + personal summary (if PERSONAL mode)
2. RAG Retrieval:
   ├─ 檢索 podcast_style_guide / market_narratives / scenario_playbooks
   └─ 組裝風格 + 敘事 + 情境知識
3. Build System Message:
   └─ "你是 Podcast 主持人+分析師。遵循風格指南。開場含日期+概覽，結尾含投資提醒。" + RAG context
4. LLM Call:
   ├─ model: OPENAI_MODEL
   ├─ structured output: PodcastLLMOut (title + bullets + lines[])
   └─ fallback: build_fallback_podcast(req) (無 AI 時的模擬稿)
5. TTS:
   ├─ 若 req.lines → create_dialogue_wav() → 雙聲線 WAV
   └─ 若純文字 → `OPENAI_TTS_MODEL`（預設 `gpt-4o-mini-tts`）streaming → MP3

【輸出】
{
  title: str,
  bullets: [str],
  script: str,
  estimated_seconds: int,
  lines: [{speaker, text}]
}
```

**RAG 注入點**：步驟 2–3（風格指南 + 敘事知識 → system prompt）
**Fallback**：無 OpenAI key → build_fallback_podcast() 回傳範本稿
**目前狀態**：implemented；無 OpenAI key/provider 失敗時回 deterministic fallback，TTS 另有瀏覽器 fallback。

## 16-5 健康度分析資料流 (`/portfolio/analyze-llm`)

```
【輸入】
├─ holdings: [{ticker, weight}]  # 配置清單
├─ total_capital: float
├─ risk_profile: str
└─ access_token: str             # @token_required

【處理】
1. calculate_portfolio_risk_health(req):
   ├─ Top1 weight / Top3 weight
   ├─ Annual volatility (from yfinance 90d)
   ├─ Max drawdown
   └─ 回傳 {top1_weight, top3_weight, annual_vol, max_drawdown}
2. RAG Retrieval:
   ├─ 檢索 risk_health_guide / investment_rules / scenario_playbooks
   └─ 組裝健康度解讀知識
3. Build Prompt:
   ├─ 持幣文字 + 數值指標
   └─ system: "你是財富管理顧問。根據配置原則分析。" + RAG context
4. LLM Call:
   ├─ model: OPENAI_MODEL_PORTFOLIO (gpt-5.4)
   └─ structured output: PortfolioLLMOut (narrative + highlights)
5. Return: risk_health (原始數值) + narrative (AI 解釋) + highlights

【輸出】
{
  risk_health: {top1_weight, top3_weight, annual_vol, max_drawdown},
  narrative: str,                # AI 生成的解讀
  highlights: [str]              # 重點提醒
}
```

**RAG 注入點**：步驟 2–3（健康度指南 → system prompt）
**數值保護**：risk_health 在 LLM 呼叫前已完成，LLM 只能讀取不能修改
**目前狀態**：partial；即時數值分析與 LLM/fallback 已實作，但不寫入文件中的 `portfolio_health_reports`。

## 16-6 Agent 計畫資料流 (`/api/agent-plan`)

```
【輸入】
├─ goal: str                     # 使用者任務描述
├─ profile: str                  # 風險偏好
├─ budget: str                   # 預算範圍
└─ access_token: str             # @token_required

【處理】
1. Fallback Check: 若無 OpenAI client → 回傳 deterministic fallback
2. RAG Retrieval:
   ├─ 檢索 investment_rules / scenario_playbooks / risk_health_guide / market_narratives
   └─ 組裝情境 + 配置知識
3. Build Prompt:
   └─ "你是 AI Agent。任務={goal}, 風格={profile}, 預算={budget}。" + RAG context
4. LLM Call:
   ├─ structured output: AgentPlanOut
   └─ fallback on error: 使用 fallback (規則版 steps/risks/next_action)
5. Allocation Generation:
   └─ build_agent_allocation(profile, budget) → 市值加權 + SFI 分層

【輸出】
{
  summary: str,
  allocation: [{symbol, weight, amount_usd, reason}],
  steps: [str],
  risks: [str],
  next_action: str
}
```

**RAG 注入點**：步驟 2–3（情境 playbook + 投資原則 → prompt）
**Fallback**：若無 OpenAI key → 完整 deterministic fallback（規則版建議）
**目前狀態**：implemented；產生建議與 paper-trading 動作，不會執行真實交易所交易。

## 16-7 知識庫更新流程

```
【觸發條件】

└─ 重啟 Flask → KnowledgeBase.load_all() 重新載入

【未來自動化流程 (Phase 2)】
```

## 16-8 使用者上下文摘要流程

```
【資料來源】
├─ Supabase ai_messages → 對話歷史
├─ Supabase sim_positions → 持倉摘要
├─ Config.SIM_STRATEGY_PRESETS → 風險偏好參數
└─ localStorage (前端) → UI 狀態

【摘要邏輯 (目前)】
├─ AI Chat: history_rows → map_history_rows() → 載入對話上下文
├─ Agent Plan: profile + budget → build_agent_allocation()
└─ Podcast (PERSONAL): portfolio_summary → 注入開場介紹

【未來個人化 (Phase 2)】
├─ 使用者行為分析: 常看幣種/常問問題/風險偏好變化
├─ 摘要向量化: 每次對話後更新 user_profile_embedding
└─ 注入所有 AI 請求的 user_context 欄位
```

**目前狀態**：MVP（對話歷史 + 持倉摘要） | Phase 2: 行為分析 + embeddings
