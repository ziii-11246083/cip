# 第 11 章 複評口頭答辯重點

> 更新日：2026-08-20。回答以 `docs/18-系統功能與資料一致性矩陣.md` 與 `docs/19-複評證據包.md` 為證據基準；不要沿用舊版不存在的 GMGN/WHOIS/交易所同步/歷史回測宣稱。

## 11-1 核心論述

> Smart Invest 是繁體中文的加密資產風險教育與決策輔助平台。我們不保管資金、不執行真實交易、不保證獲利；核心是把市場、組合、可疑文案與 AI 回答的風險，整理成可理解、可追溯、可測量的流程。

### 三分鐘版本

1. **問題（30 秒）**：新手面對碎片化資訊、可疑邀約與高度波動，常在沒理解風險前做決策。
2. **解法（60 秒）**：市場/SFI、健康度、可疑文案規則、RAG AI 教練、紙上交易與假設式壓力測試。
3. **信任（60 秒）**：RAG 記錄 query/answer/實際來源，citation 可看、feedback 可回報；15 題離線 runner 與 regression gate 已建，但人工 baseline 尚未核准。
4. **限制（30 秒）**：公開錢包只做 Ethereum Mainnet 唯讀 Beta code，DB 未部署；訂閱/金流/交易所/歷史回測仍未實作。

## 11-2 常見問題與 90 秒回答骨架

### Q1：和 TradingView、CoinStats、Koinly 有什麼不同？

- TradingView 的強項是圖表、指標與 alert；CoinStats 是跨錢包/交易所 portfolio；Koinly 是稅務與對帳。
- 我們不宣稱功能更廣，而是聚焦「投資前風險理解」：繁中解釋、FOMO/集中風險、可疑文案、RAG citation 與 synthetic stress test。
- 我們目前弱項也很明確：同步只到 Ethereum 公開地址 code MVP、沒有稅務、沒有完整歷史回測、沒有正式付費流程。
- 定價與官方來源見 `docs/05` §5-4。

### Q2：AI 不是只把問題丟給 GPT 嗎？

- 請從資料流回答：Router → Query rewrite → hybrid retrieval → rerank → prompt injection → LLM → trace/citation。
- 只把真正注入 prompt 的 source 當 citation；RAG unavailable 時固定標 degraded/fallback，不假裝有資料。
- AI 還可呼叫市場價工具，Scam/Health/Agent 另有 deterministic 規則與數值計算，不把數學交給模型猜。
- 證據：`services/rag_service.py`, `services/prompt_builder.py`, `services/rag_trace_service.py`。

### Q3：怎麼證明 RAG 準？

- 正確回答是「現在能量測，尚不能宣稱準確率」。
- 線上 trace 保存 sanitized input、actual sources、answer、model、latency、fallback/status；feedback 是主觀訊號，不是 ground truth。
- 離線 runner 有 15 題、P@K/Recall/MRR/NDCG/source/keyword/latency，並有 baseline approval 與 regression gate。
- 15 題仍 `pending_review`、沒有 approved clean baseline；下一步是由老師/領域人員審核 expected sources/topics，再從 clean commit 核准 baseline。

### Q4：詐騙功能掃描了什麼？準確率多少？

- 目前只分析使用者貼上的**可疑文案**。
- 第一層固定文字紅旗（保證獲利、助記詞/私鑰、冒名客服、緊急轉帳），第二層本地案例 RAG，第三層 LLM 結構化說明；明確 high rule 不能被 LLM 降級。
- 沒有 GMGN、WHOIS、合約、網域、PTT 或鏈上掃描，也沒有人工標記 scam dataset，所以不報 accuracy/recall。
- Demo 用「保證每天 10%，請提供助記詞」，展示 reasons/evidence/uncertainty 與安全警語。

### Q5：模擬交易、壓力測試、歷史回測差在哪？

- 即時 paper trading 會記錄虛擬訂單、持倉與 equity curve。
- 壓力測試複製一次 snapshot，以固定 seed 比較 normal/bull/bear/black_swan 與三種策略；只回傳結果，不寫帳本。
- 壓力測試的 multiplier 是 synthetic terminal anchor，不是預測。
- 本產品目前沒有完整歷史回測引擎；只有方法文件，不能把 stress test 說成 backtest。

### Q6：資產自動同步做到哪裡？

- 已完成 Alchemy Portfolio API + Ethereum Mainnet 公開地址唯讀的 adapter、資料契約、四表 migration、atomic commit RPC、member UI 與 fake integration tests。
- 不收助記詞、私鑰或使用者 API secret；真實 snapshot 與 sim ledger 分離，失敗保留 last-good。
- 但 migration 尚未在正式 Supabase 執行、沒有 live provider test、沒有 scheduler、沒有交易所 API，也沒有真實付費 entitlement。
- 因此只能說「code/migration ready 的單鏈 Beta MVP」，不能說「付費會員已自動同步所有資產」。

### Q7：資料與權限安全怎麼做？

- Supabase Auth JWT；admin 只信 verified `app_metadata`，不信 email/user metadata。
- RAG 與 asset migrations 啟用 RLS：一般使用者只讀自己的資料；service role 寫入，且不回退 anon/generic key。
- Trace 對 PII/JWT/API key/私鑰等遮罩；API/log 只回固定錯誤碼。
- 尚未執行 migration 的表不能宣稱正式 RLS 已驗證；上線前需 test project integration。

### Q8：商業模式能損平嗎？

- Free/Pro US$9.99/Premium US$24.99 是**待驗證定價**，不是已上線商品。
- Base token 假設下，每次文字回答約 US$0.017145；在 80/20 plan mix，單位貢獻約 US$9.52。
- Base 固定服務 + TTS 預算 US$102 時約需 11 位付費會員損平；但這不含人力，且 Stripe 台灣費率、稅、退款、留存與願付價格仍待驗證。
- 不回答「6–12 個月一定損平」；改說會先用 10–20 位訪談與 conversion/retention data 驗證。

### Q9：GitHub 怎麼證明團隊做了什麼？

- 展示具體 commit → 檔案 → 使用者問題 → 測試/結果，不用 commit 數量排名。
- `origin/08/20` 目前是 `5b7f523`；Task 05A 後續到 Task 12 仍是本機 verified worktree，未再次 push。
- `origin/main` 是舊且分歧的 ref，不拿來代表現在版本，也不改寫歷史。
- 成員 alias、代表 commits 與 90 秒答題卡見 `docs/19` §19-3。

### Q10：目前最大風險與下一步？

1. **P0—品質證據**：人工審核 RAG 15 題並核准 clean baseline，之後每次 release 跑 regression。
2. **P0—部署驗證**：在 Supabase test project 實跑 RAG/asset migrations、RLS/RPC/concurrency，不能只依 static validator。
3. **P1—價值驗證**：找 10–20 位使用者做風險理解、citation 信任、同步操作測試。
4. **P1—商業基礎**：確認定價、台灣金流/退款/稅務與 entitlement，再決定是否做 checkout。
5. **P2—擴充**：交易所同步、scheduler、歷史回測、notifications 都應另案，不塞回既有核心流程。

## 11-3 現場 8 分鐘路徑

1. 功能矩陣：說清楚 implemented/partial/planned。
2. AI Chat：citation + feedback + degraded 邊界。
3. RAG eval：15 題與 regression，但不宣稱準確率。
4. 可疑文案：規則高風險與未做外部掃描。
5. 會員資產：公開地址唯讀與 deployment limitation。
6. Paper stress：同 seed 四情境、ledger 不變、非歷史回測。
7. 成本/競品：現場重算 Base 與說出競品更強處。
8. GitHub：開 `08/20` checkpoint，再揭露本機尚未推送範圍。

詳細秒數、成員分工與 33 項 evidence matrix 見 `docs/19-複評證據包.md`。
